## 설계 기준

📐

**설계 기준**

혼자 주차 중 준비하는 차량 가로 화면을 우선 검토한다. 주행 중 편집·입력을 제공하지 않는다. 와이어프레임의 시나리오 버튼과 상태 패널은 검토용이며 제품 화면이 아니다.


## 화면별 구성

| 화면 | 목적 | 입력·표시 | 버튼·동작 |
| --- | --- | --- | --- |
| W01 시작 | 이번 사용자와 준비 환경 확인 | 부모/자녀, 혼자 있음, 안전한 주차 확인 | 다음, 내용 비우고 그만하기 |
| W02 자기 이야기 | 실제 소재 정리 | 장면 필수, 느낌·생각/선택/남은 생각은 선택 | 다음, 관심사로 전환, 중단 |
| W02B 관심사 | 이미 아는 화제 준비 | 관심사와 알게 된 경로 필수 | 다음, 자기 이야기로 전환, 중단 |
| W03 수정 | 자기 말과 공개 범위 결정 | 입력 기반 결과, 직접 편집 | 다음, 원래 소재 보기, 중단 |
| W04 안내 선택 | 안내의 노출과 횟수 결정 | 기본 꺼짐, 일반 문장 예시, 상대도 들음 설명 | 안내 없음/1회, 완료·내용 비우기 |
| W05 준비 완료 | 개인 내용 제거·이동 준비 | 내용 제거 완료, 선택한 안내 여부 | 실제로는 앱 닫기/주행 수명주기 연결. 모형 출발 버튼은 검토용 |
| W06 안내 대기 | 운전자 입력 없이 안내 처리 | 개인 내용·입력 없음. 검토 모형만 대기·보류 상태 표시 | 제품에 반복 시도 버튼 없음 |
| W07 종료 | 해당 이동의 개입 마침 | 안내 완료·무음·중단 결과는 검토 모형에서 확인 | 다음 준비는 주차·혼자 조건 재확인 |
| W08 보호 종료 | 진행 불가 상황에서 초안 제거 | 내용 제거와 다시 시작 조건 | 조건 충족 시 처음으로 |

## 주요 문구

💬

**주요 문구**

- 시작: “지금 사용하는 분은 누구인가요?”
- 준비: “내게 있었던 일 하나부터”
- 수정: “내 말처럼 다듬어 보세요.”
- 안내: “기본은 안내 없음이에요. 켜면 함께 탄 사람도 들을 수 있어요.”
- 완료: “준비한 내용은 비웠어요. 이제 기억나는 만큼, 내 말로 이야기해요.”
- 중단: “주변 상황이 괜찮을 때 다시 시작해요.”

## 입력·오류 규칙

- 역할 미선택·준비 조건 미확인: W01 유지, 빠진 조건 안내.
- 실제 장면 없음: W02 유지, 한 줄 입력 요청.
- 관심사 또는 출처 없음: W02B 유지, 두 항목 입력 요청.
- 수정 결과가 공백뿐임: W03 유지, 한 줄 이상 남기도록 안내.
- 길이 제한은 ‣의 기준을 적용한다.

## 접근성·표현

👁️

**접근성·표현**

입력 라벨과 오류 메시지를 제공하고 키보드로 이동할 수 있게 한다. 색만으로 상태를 구분하지 않는다. 첫말을 잘해야 한다거나 상대의 마음을 열어야 한다는 문구를 쓰지 않는다.

실제 글자 크기·터치 영역·야간 밝기·입력기 사용성은 차량 디스플레이에서 검증한다.
